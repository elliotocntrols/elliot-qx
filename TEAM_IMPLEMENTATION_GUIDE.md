# Elliot Qx Team Implementation Guide

## Objective
Use Qx as the operational QA and commissioning source of truth for the pilot project, while approved drawings, specifications, sequences, statutory requirements and authorised test procedures remain the technical authority.

## Week 1 — Configure
- Nominate Qx owner and project pilot.
- Confirm project naming, system codes, equipment tags and user roles.
- Review Template Library and lock the standard Elliot QA / commissioning templates.
- Import one real BMS points list and one MSSB schedule into a training project.
- Create logins for the pilot team.

## Week 2 — Pilot in parallel
- Site team records QA, BMS I/O, defects and evidence in Qx.
- Keep existing contractual records in parallel for one week only while outputs are checked.
- PM reviews Command Centre and Completion Matrix daily.
- Commissioning lead validates generated check sheets against project requirements.

## Week 3 — Field adoption
- Start each day from My Work / Field Hub.
- Every failed commissioning check becomes a punch item and is assigned before end of shift.
- Photos/evidence are attached to the asset/test rather than stored separately.
- PM uses Qx readiness in internal coordination meetings.

## Week 4 — Source of truth on pilot
- Stop duplicate internal spreadsheets once the pilot checks are accepted.
- Use Qx for witness tracking, turnover readiness and internal handover dossier.
- Run a lessons-learned review and update templates.
- Decide rollout sequence for remaining projects.

## Daily role workflow
- Site technician/electrician: Field Hub -> Asset -> QA/BMS I/O -> Evidence -> Punch.
- BMS engineer/commissioning technician: BMS I/O -> PFC/FPT -> rectify failed points -> prove graphics/alarms/sequence.
- Project Manager: Command Centre -> Completion Matrix -> Alerts -> Witness -> Turnover.
- QA/Admin lead: Template Library -> controlled documents -> user/admin -> closeout reports.

## Governance
- Do not auto-approve AI/generated commissioning sheets. Engineer/PM review is mandatory.
- Preserve approved project document revision references.
- Category A punch blocks completion until verified.
- Weekly backup/restore checks and monthly user/role review are recommended during rollout.
